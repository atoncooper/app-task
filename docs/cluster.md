# 集群部署与运维指南

> 单节点部署见 [README.md](../README.md)。本文讲什么时候需要多实例、怎么加节点、
> 怎么配分工，以及节点出问题时的行为。实现原理见 [design.md](design.md)。

## 1. 什么时候需要多实例

- **高可用**：一台机器宕机，任务不能停；
- **扩容**：积压任务多、单机消化不过来；
- **隔离**：某台机器兼职干别的，只让它承担一小部分任务量。

不需要多实例时，单节点就是最简形态——集群相关配置全部可以不碰。

## 2. 加第二台节点（两种方式）

### 方式 A：compose 一条命令（同一台机器上的第二实例）

```bash
docker compose --profile ha up -d app-task-ha
```

这会启动 `app-task-ha`（控制台 http://localhost:8011），它已预设为
**manager 角色**（权重 1，少拿任务）。

### 方式 B：加入一台新机器

1. 在**现有集群**的控制台「集群」页点「加入节点」（或用命令行
   `at node join --name worker-2 --weight 4`），填一个节点名和权重；
2. 页面会生成一段**加入指引**（环境变量 + 启动命令），复制到新机器执行；
3. 新节点启动后自动出现在名册里，状态变为「存活」。

> 新节点的 MySQL 连接串（指引里的占位符）请从你的密钥/密码管理渠道获取，
> 不会在页面上显示。

## 3. 权重：谁多干谁少干

每个节点有一个**权重**（默认 1），决定它分到多少任务：

- 所有节点权重相同 → 平均分；
- 4 台机器、1 台是 manager（还兼跑别的服务）：manager 设 `1`，其他三台设
  `4` → manager 只承担一个 worker 的四分之一；
- 权重最高的节点宕机 → 剩余节点自动补上它的份额，不需要人工调整。

在控制台「集群」页或 `at node ls` 可以看到每个节点的权重和正在处理的任务数。

## 4. 节点挂了会怎样

- 节点失联约 **30 秒**后，其他节点判定它已下线，**立即接管**它手上正在
  执行的任务并重新执行；
- 被接管的任务在「任务管理」页可以看到归属变化；
- 接管期间不会有任务丢失——最坏情况是某条任务被执行了两次（原节点其实
  没死透、只是卡顿），因此**执行接口请做幂等**（用请求头 `X-Task-Id` 去重）。

## 5. 多实例的共享配置

| 配置 | 单实例 | 多实例 |
|------|--------|--------|
| 数据库 | 各自独立 | **指向同一个 MySQL**（这是组网的唯一硬要求） |
| 控制台会话 | 内存即可 | 若多个控制台共用一个域名，设 `APPTASK__WEBUI__SESSION_STORE=redis` |
| 加入准入 | 默认 open（自动注册） | 可设 `APPTASK__CLUSTER__ADMISSION=pre_approved`：未预先登记的节点拒绝启动 |

## 6. 验证清单

```bash
at node ls        # 所有节点都在列、状态"存活"
at ps             # 任务在多个节点间分摊（看认领列）
at logs           # 每条任务只有一次执行记录
```

停掉一台节点做演练：30 秒内其任务被接管，无任务丢失。

## 7. FAQ

**Q：同一个任务会被执行两次吗？**
正常不会。极端情况（节点在执行瞬间断电）下可能重试一次——这是"宁可重复、
不可丢失"的设计，所以执行接口请幂等。

**Q：两台机器时钟不一致有影响吗？**
容忍秒级偏差；多实例部署请确保各机器 NTP 同步（云主机/容器宿主机默认满足）。

**Q：数据库宕机会怎样？**
所有节点暂停调度（不会丢任务），数据库恢复后自动继续。
